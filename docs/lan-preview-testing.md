# Hotaru 局域网插件开发版实测

用同一个 ZIP 在两台 Windows 10／11 x64 电脑上测试。完整解压后打开 `HotaruDev.exe`，按 **Ctrl+Alt+H** 或用托盘打开 Hotaru，再进「设置 → 插件」。开发版与正式版的数据、登录项和默认热键独立；插件初次使用时均关闭。

1. **连接**：两台电脑连同一个可信的 Wi-Fi 或有线网络，Windows 网络配置文件选「专用」。在两台电脑上分别填写不同的设备名；在一台生成长码并保存，将同一码填到另一台。两边分别开启同一个插件，设备列表应出现对方。若 Windows 显示防火墙提示，只允许专用网络；应用不会替你修改防火墙。访客 Wi-Fi 或启用设备隔离的网络可能无法发现。

   插件页分别显示「已发现设备」和「已配对设备」。已发现但尚未认证的设备会显示 IP、设备 ID 尾缀和当前认证阶段；只有安全码认证成功后才会进入已配对列表并参与剪贴板同步。若自动发现仍为空，可在“已发现设备”下输入对方 IPv4（例如 `192.168.1.20`）点击「探测」，用于排查组播或广播被网络设备过滤的情况。

2. **错码与换码**：关闭两边插件，把另一台改成不同的码再开启，应无法配对。改回相同安全码后等待重新发现。配对后只改一端的码，旧连接应断开，两边改成同一码后可重新配对。切换成公用网络后，连接应在几秒内断开。
3. **剪贴板**：先关闭文件分享，仅启用剪贴板插件。分别在两台复制新文字和一张小截图，对方应可以粘贴；不会补发旧内容，也不应往返刷新。「复制已保存的码」产生的剪贴板内容应只留在当前机器，且不出现在 Hotaru 剪贴板历史。停用剪贴板后再复制，不应同步。
4. **文件和目录**：关闭剪贴板，仅启用文件分享。选择对方，在发送区拖入一个包含中文文件名、空目录和较大文件的目录。对方收到托盘提示后打开文件分享设置，确认前接收目录应无新增文件；确认后显示进度并落入选定目录下的「Hotaru 接收」。再传一次应创建「Hotaru 接收 (2)」保留两份。
5. **异常**：试一次拒绝，试一次传输中取消，再试一次传输中断网。失败或取消应清理未完成的接收文件。恢复连接后可用「重试」重新发送。保持另一插件开启时关闭文件分享，应停止文件收发且不影响另一插件。

请记录失败步骤、两台电脑的 Windows 版本、网络类型和插件页状态；不用发送安全码或文件内容。预览只在 IPv4 专用网络自动发现，单机同时处理一项发送和一项接收，首版无共享目录浏览与断点续传。

## DNS-SD 与 UDP fallback 诊断

如果启用插件后进程立即退出，优先使用本轮修复包；旧版曾把 `DNS_REQUEST_PENDING` 当成失败并释放仍由 DNS API 使用的请求内存，Windows 事件日志会记录 `0xc0000374` 堆损坏。本轮已改为保留注册、浏览和解析上下文，取消/注销完成后再释放，并覆盖启用后关闭的生命周期自测。

开发版优先在每个 Windows 专用 IPv4 网卡调用系统 DNS-SD，服务类型为 `_hotaru._tcp.local`。TXT 只包含 `proto=HL01`、随机设备 ID、能力位和构建版本；设备名与安全码仍只在 TCP/SPAKE2 认证后交换。设置页的网络状态应显示 DNS-SD 注册结果、专用网络状态和 TCP 监听状态。

若 DNS-SD 注册、浏览或解析失败，程序自动继续使用现有 UDP 组播，并向每个专用子网发送定向广播。发现列表中的设备仍要经过 SPAKE2 才会进入已配对列表。专用网卡筛选、TCP 绑定、UDP 绑定和组播加入分别显示。TCP 超时仅说明没有建立连接，单凭超时无法区分防火墙、路由和无线隔离。

开发预览版从插件详情页的「打开诊断日志目录」查看连接日志。

## 搜索快捷入口

输入完整快捷词 `jtb`（可在剪贴板插件设置中修改或关闭）显示当前系统剪贴板的文本预览、图片缩略图或空状态；结果只读，不新增局域网历史。输入 `@` 或 `@设备名前缀` 只列出已认证并启用文件分享的设备，按 Enter 后选择文件或文件夹发送。未配对、插件关闭或设备断线时，搜索窗口直接显示原因，不打开空的文件选择器。

## 固定端口与重连

LAN 的 TCP 和 UDP 使用固定端口 `45456`。组播、广播或 DNS-SD 未发现设备时，程序会在专用 IPv4 子网内分批探测。TCP 的 `HL01R` 注册探测只返回候选 ID 和端口，仍须建立独立连接并完成 SPAKE2 认证。注册探测与认证连接分别限速。

通过认证后，开发版会保存最近的对端 IPv4；重启后优先探测缓存地址。诊断日志可区分发现、连接与认证。若连接失败，结合两端日志和 Windows 网络配置判断原因。模块仍仅随开发预览包交付。

## 两端无法监听或找不到设备时

1. 两台电脑都从托盘退出旧的 **HotaruDev**，再完整解压并运行相同的新开发包。旧进程未退出时，单实例机制会把启动请求交给旧进程。
2. 打开「设置 → 插件 → 局域网剪贴板共享 → 打开设置」，确认已保存安全码并启用插件。记录页面上的 TCP、UDP 和组播状态。
3. 等约 10 秒。若仍找不到对方，在两端的「已发现设备」下分别填写对方 IPv4 并点击「探测」；再等约 5 秒。
4. 点击「打开诊断日志目录」，发送两端的 `lan-diagnostics.log`，注明哪份来自哪台电脑。若当前文件缺少本次启动记录，再补发 `lan-diagnostics.previous.log`。

日志只写到开发版数据目录的 `lan-preview` 子目录，单份上限 128 KiB，最多保留当前和上一份。不自动上传。日志含时间、局域网 IPv4、接口索引、端口和连接结果，不记录设备名、安全码、剪贴板内容或分享文件名。只需发送日志，不要发送同目录的 `settings.json`。

若 TCP 和 UDP 都无监听，先查看本机网络配置与绑定结果。防火墙仍可影响入站流量；远端可达性与本机是否有监听是两项独立检查。

## 能发现设备，但没有自动配对时

1. 两台电脑都退出旧开发版，从同一个新包完整解压后启动。在两边保存完全相同的安全码，确认均已开启局域网剪贴板共享。安全码由各自 Windows 用户加密保存，在另一台电脑上需要重新输入。
2. 等 10 至 15 秒。对方设备名应自动进入「已配对设备」，无需点击「探测」或确认配对。在其中一台复制测试文字，确认另一台能粘贴，再换方向测试。
3. 若仍停在等待、连接或校验状态，从两端的「打开诊断日志目录」取 `lan-diagnostics.log`。日志按阶段区分发现候选、本地绑定失败、TCP 连接失败、SPAKE2 校验、认证成功和已配对。只发日志，不发安全码或设置文件。

LAN 的 TCP 和 UDP 均通过选中的专用网卡直连，应用代理设置不影响这条路径。首选连接方向不通时，另一端可自动尝试反向建立同一条双向会话。如果两端的入站连接均被拦截，发现仍可能正常，但不会完成配对。
